# Connected maps

Camp → bunker stairs → emergency bunker. Walk mode and Play use the same travel controller. Build always returns to camp; Stop restores the original editor world and view. Runtime map state is session-only, just like the existing Play session, and is never written into the saved camp draft.

Camp, the **East approach**, **Village approach**, **Village outskirts**, **Works approaches**, **Works grounds**, **Works meadow** **Southern works** the **Camp return** and **South camp ground** form one continuous outdoor world. Follow the southeast stone path onto the woodland junction, then either continue east into the cooler works ground or take its dirt path north through the village trail. Both the village trail and outskirts now connect east to the works service track, closing a second walking loop. The eastern service-road branch leads through an open works yard and dirt lane. The new meadow above the yard closes its northeast corner with one connecting path and wide freely walkable stretches of grass and dirt. The works routes also continue south into a broad worn clearing and a narrower scrap-outskirts trail, with open ground between them. The road-free southern strip connects west from the works clearing beneath the camp’s southeast approach, and two further pieces now reach directly below the central camp. The camp’s southern stone exit becomes a narrow dirt footpath, with a broad open clearing beside it. There is no outdoor portal, fade, teleport, world swap or reset. Walk, Play and Build share this footprint. The bunker remains a separate interior with its existing fade.

## Adding an interior

1. Add its image to `public/survival/maps/…` with a versioned filename/key. Keep image dimensions modest enough for mobile decoding. Use additional separately loaded detail only when needed; do not load every map at launch.
2. Register a `SceneDefinition` in `src/world-scenes.ts`: a unique ID, dimensions in world units, image, walkable floor polygon, furniture blockers, optional foreground masks, and named arrival positions. Geometry and image dimensions are independent. Floor geometry must accommodate the player's 19-unit radius.
3. Define portals by polygons with a destination scene ID + spawn ID. For an exit use `{return:true}`: the controller remembers the actual entrance, including which copy of a building was used. Every portal provides a clear return spawn outside its own trigger.
4. To attach a portal to an outdoor asset, add an `ASSET_CONNECTIONS` entry. Coordinates are normalized to the complete asset image, transformed using the existing placement dimensions, scale, rotation and flips. `waitForAnimation` lets a step-on door finish opening before travel.
5. Optionally supply a scene layout for placed assets. The scene's dimensions/floor replace camp bounds during movement. Use the same shared asset registry and dimensions; no new renderer is needed.

`SceneTravel` owns active and visited world instances, a return-route stack, portal suppression and a 180 ms fade in each direction. It transfers player health, inventory, equipment and run counters. Doors, stations, cooking state, creatures and drops stay on their own map. Portals wait for destination resources before fading and validate an arrival before switching. Failed downloads/blocked entrances leave the source world usable, with retry outside the gameplay viewport. A generation token prevents late loads from undoing Stop, Build or Restart. New-map simulation is paused during the fade, input is cleared on arrival, and presentation interpolation resets across scenes.

`SceneResourceCache` prefetches one adjacent destination, deduplicates in-flight loads, and retains up to three extra maps (current, return and next). Camp/character artwork stays loaded. The existing three-request artwork queue handles fetch/decode. A texture is warmed on the existing Skia surface before a destination is declared ready; at most one warm-up is added per rendered frame. Eviction accounts for shared keys and pending loads. CPU world state survives image eviction; revisiting a distant evicted map reloads its images without resetting that map. Maps never remount the canvas, React workspace, or character animation system.

The supplied bunker JPEG is unmodified (1254 × 1254). Its beds, shelf and bench are background artwork with collision, not interactive furniture assets. The front wall masks reuse the same image so the character can pass behind them.
