# Humans Remain base-production catalogue

Updated 6 October 2026. The canonical source is `src/base-catalogue.json`, transformed reproducibly from `docs/archive/base-catalogue-before-restructure-2026-10-06.json` by `scripts/restructure-base-catalogue.mjs`. The latter is a frozen before-migration backup. `docs/archive/base-catalogue-migration-report.json` lists each rename, reclassification, tier display change and batch move; no original ID was deleted or remapped. The live database had zero saved override rows at the moment of backup; its read-only snapshot is in `docs/archive/saved-marks-before-restructure-2026-10-06.json`. Existing D1 rows remain in place and the new migration only adds two nullable columns.

The browser main menu opens `#checklist`. The public, read-only HTML export is `/checklist.html`. Both use the same catalogue and live saved marks. The export includes all three views directly in server-returned HTML. It needs no sign-in or JavaScript. The owner-only editing API accepts only trusted Sites identity headers and same-origin PUT requests. ChatGPT MCP reads the same catalogue; it has no write tool.

Three views: Build catalogue groups complete upgrade chains by function; Asset production tracks the same tier sprites and each canonical reusable prop, fixture, state, effect or UI task once; Systems and testing lists implementation work and acceptance checks. A build record can appear in the art view because its own tier needs a distinct sprite; shared props link to one canonical art record. Linked historical concepts such as bedroll, cot, map board and hearth cooking remain visible without counting duplicate artwork commissions. Search and filters cover category, family, phase, type, art readiness, implementation and blockers.

The displayed tier is independent of the stable ID. `base_cooking_t1` is now integrated hearth cooking with no independent tier; `base_cooking_t2` displays dedicated cooking tier 1. `exp_radio_t1` is a broken fixture awaiting restoration; `exp_radio_t2` displays functional radio tier 1. The old IDs and images remain intact. The generator is separately marked present in the current prototype even though its buildable progression is later. Moving a planned tier to a later phase does not disable runtime features.

Phases: B0 confirms asset scale, terrain separation, placement, resource flow and multiplayer ownership contracts. B1 completes one first-night playable kit with hearth, manual water, shared storage, basic workshop and medical supplies, lights, walls and working gate. B2 adds shelter, water reserve, basic crop loop and selected early upgrades. B3 builds tested core progression. B4 adds advanced services and powered utilities. B5 contains only validated optional expansion. Cosmetic work is lower priority unless needed for readability.

Physical footprint and upgrade-lot figures carried from the original plan are proposals, not final collision standards. Player clearance, door width, occlusion and export dimensions require measurement against the actual character collision and camera scale. Upgrade lots never block movement before the tier exists. Check room before charging resources. The game still uses the existing terrain; `art_clean_buildable_terrain` is a new production task and does not alter the map in this change.

The new task records include clean terrain, modular wall/gate components, seeds/crop overlays/produce, medical supplies, stock displays, pickup icons, construction feedback, authoritative shared-world rules and two-client acceptance. No artwork or gameplay was changed. Detailed source evidence is retained on existing records; reported tests are labelled previously reported. The current checklist validation reruns schema, links, display tiers, HTML generation and API permission checks, not the survival simulation.

Run `npm run typecheck`, `npm run build`, then `node scripts/check-base-catalogue.mjs`. Do not rerun the restructure script after editing the canonical JSON without first reviewing whether it would overwrite those newer edits.
